## 面试题：整卡、时间片、MPS、MIG 与 vGPU 应如何比较？

### 30 秒回答

先分清“让更多任务用上卡”和“给每个任务独立、可保证的资源”。时间片让任务分时使用；MPS 协调多进程执行；MIG 在支持的硬件上划分实例；vGPU 是虚拟设备产品方案，底层机制不止一种。没有一种名称能代替实际隔离验证。

### 用一个例子理解

开发人员偶尔跑小实验，可能更看重共享利用率；在线推理担心被邻居拖慢，更看重延迟和隔离；虚拟桌面还要看虚拟化平台兼容。先说业务要求，再比较方案，不要先认定“所有场景都应该 MIG”。

### 关键机制与取舍

- “硬切分 / 软切分”可以作为入门分类，但不是能力保证：硬件分区也有共同故障域，软件共享也不一定提供独立显存配额。先看具体限制由谁执行，基础解释见 [GPU 扫盲](/docs/gpu-virtualization/gpu-basics)。
- 按显存约束、计算调度、故障域、兼容性、重配置与许可证逐项比较。
- 区分“能启动更多任务”与“每任务获得可保证资源”，共享副本数不是物理卡数。
- 用目标负载实测尾延迟与干扰，对强隔离租户优先选择具备匹配隔离边界的方案。

### 场景与失败处理

轻量开发 Notebook 可以接受共享，但低延迟推理可能被邻居长任务拖慢。应按工作负载分池，而不是把所有 GPU 一律开最大共享倍数。

### 常见追问

**共享一定更便宜吗？** 利用率可能提高，但排队、抖动、兼容与运维成本也会增加。

**MIG 与 vGPU 是互斥概念吗？** 不应泛化，具体产品可能组合不同能力，必须核对支持矩阵。
