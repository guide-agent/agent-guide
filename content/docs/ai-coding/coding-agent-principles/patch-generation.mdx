## 面试题：生成 Patch 比重写整个文件有什么优势？

### 回答框架

小范围补丁更容易审查、归因和回滚，也更少覆盖用户已有修改。但补丁必须基于当前文件，路径和上下文匹配并不保证语义正确。实际应用前检查基线，应用后检查完整差异与受影响行为。

### 关键机制与取舍

- 限制修改范围与文件路径，注意符号链接、换行、编码和生成文件。
- 上下文不匹配时重新读取并理解差异，不盲目扩大替换范围。
- 保留原有未提交工作，区分任务相关修改与格式化噪声，必要时单独说明。

### 场景与失败处理

用户在同一函数增加了校验，Agent 依据旧片段整段覆盖导致校验丢失。应先读取当前版本，把新逻辑与现有校验合并，再补回归。

### 常见追问

**补丁应用成功算成功吗？** 不，需检查编译、调用方、测试与需求语义。

**如何恢复错误补丁？** 用改动前快照或版本差异只撤销本次部分，不重置整个脏工作区。
