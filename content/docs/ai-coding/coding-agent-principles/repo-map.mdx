## 面试题：Repo Map 有什么价值，又容易遗漏什么？

### 回答框架

Repo Map 用目录、符号、依赖和摘要帮助模型快速定位代码，不是源码的完整替代品。构建方式可以基于文本、语法树或引用图，具体取舍依语言和仓库而异。地图应注明版本，并支持回到原文件验证。

### 关键机制与取舍

- 突出入口、公共接口、依赖方向和测试位置，避免对每个文件生成同样空泛描述。
- 增量更新与提交绑定，重命名、删除和生成代码变化也要同步。
- 精确行为、异常分支和权限检查仍需读取实现，摘要可能丢失关键条件。

### 场景与失败处理

地图显示配置从文件读取，但当前代码已支持环境覆盖。若据此修改默认值，可能运行无效；应回读配置装配路径与测试。

### 常见追问

**有 Repo Map 就不需要检索吗？** 仍需要，地图负责导航，检索负责当前问题的具体证据。

**怎样评估地图？** 测定位正确率、上下文开销与修复成功率，不只看覆盖文件数量。
