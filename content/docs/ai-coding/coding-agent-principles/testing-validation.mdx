## 面试题：编码 Agent 如何证明改动经过真实验证？

### 回答框架

记录实际运行的命令、环境、退出状态和关键结果，并说明覆盖范围。静态检查、单元测试、集成与端到端各验证不同层次；不能用构建成功代替业务测试，也不能把“没有测试”写成“测试通过”。

### 关键机制与取舍

- 先用最小失败样例确认问题，再验证补丁能修复该样例且不破坏相邻行为。
- 对外部依赖失败保留证据，区分网络与环境限制，不随意改生产配置绕过检查。
- 检查测试本身是否被放宽或删除，生成快照变化需人工理解内容。

### 场景与失败处理

文档编译因旧文章外链图片超时失败，新增文章可独立编译通过。应分别报告两项结果，而非宣称全站构建成功或删掉原图片掩盖问题。

### 常见追问

**没有运行环境还能交付吗？** 可以交付明确未验证范围的改动和验证步骤，但不能伪称上线可用。

**覆盖率达到目标就充分吗？** 仍要检查断言质量、故障路径、权限与真实任务覆盖。
