## 面试题：怎样使用 Claude Code，而不把产品宣传当验收？

### 回答框架

以实际仓库任务建立闭环：提供目标和约束，检查上下文与工具权限，应用最小修改并运行测试。Claude Code 的插件、命令和代理扩展可以改变工作流，但安装扩展不代表其行为自动可信。具体能力和设置以所用版本官方文档为准。

### 关键机制与取舍

- 读取项目约定，记录已有修改和允许范围，避免工具替用户提交无关内容。
- 审查插件的命令、hooks、MCP 和外部依赖，确认会执行什么、能访问哪里。
- 用任务结果、差异与验证记录评价，不用生成速度或对话长度代替质量。

### 场景与失败处理

代码审查插件报告“无问题”，但没有运行测试。应把静态审查与实际验证区分，并对高风险逻辑回读源码和执行相关测试。

### 常见追问

**公开 GitHub 仓库等于全部核心源码吗？** 不能这样推断；所取快照主要提供说明、插件与反馈入口，不据此声称审计了完整运行时。

**应该复制网上所有配置吗？** 不，按版本、环境与授权需求逐项核对，避免引入额外权限。
