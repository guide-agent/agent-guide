## 面试题：给 Coding Agent 的任务怎样拆，才容易验收？

### 回答框架

按可独立验证的行为或接口拆任务，而不是按“写代码、再优化”这类模糊阶段。每个任务注明输入、允许修改范围、产物和验收命令。先识别依赖与现有未提交改动，再决定顺序或并行。

### 关键机制与取舍

- 把未知信息的调查与确定改动分开，先确认调用链、配置和测试基线。
- 接口变更明确调用方与兼容要求，跨模块任务保留统一集成负责人。
- 完成条件包含失败路径与回归，不以生成文件或代码行数判定完成。

### 场景与失败处理

“给 API 加缓存”还需要确认租户隔离、缓存键、失效和并发行为。先落实这些约束，再拆实现和测试，避免只交一个缓存装饰器。

### 常见追问

**任务拆得越小越好吗？** 过碎会增加协调和上下文交接，优先围绕完整可验收行为。

**遇到需求歧义怎么办？** 能从代码和文档确认的先查，涉及业务选择且无法推断的再向用户澄清。
