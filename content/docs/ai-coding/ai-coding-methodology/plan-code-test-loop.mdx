## 面试题：Plan、Code、Test 循环中的测试应该何时开始？

### 回答框架

在改代码前就确定验收标准和基线，必要时先复现失败。实现最小改动后运行最相关检查，修复本次引入的问题，再扩大到适用回归。计划、实现和测试应相互反馈，而不是最后才运行一个构建命令。

### 关键机制与取舍

- 先记录现有失败，避免把历史问题误算成本次回归，或用历史失败掩盖新问题。
- 每次修改保持可理解差异，测试结果关联具体提交或工作区状态。
- 工具不可用、外部依赖超时与代码失败分别报告，不把未运行写成通过。

### 场景与失败处理

修复边界条件后测试仍失败，原因是新增断言暴露另一条分支。先定位是否由本次改动触发，不要删除断言或放宽验收来换绿色。

### 常见追问

**测试通过就是完成吗？** 还需差异审查、需求覆盖和未测试风险说明。

**测试很慢怎么办？** 先跑受影响测试与静态检查，再按风险运行全量必跑项，不默默跳过。
