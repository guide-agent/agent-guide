## 面试题：AI 生成代码应该怎样审查？

### 回答框架

优先找行为错误、回归、权限问题与缺失测试，而不是先挑风格。沿输入、状态变化、输出和调用方检查差异，核对修改是否满足原始需求。模型给出的审查结论需要代码和测试证据，不能因措辞自信就接受。

### 关键机制与取舍

- 按严重度报告发现，给出具体文件、触发条件、影响和可验证依据。
- 检查空值、错误分支、并发、资源释放、数据兼容及跨租户隔离。
- 审查新增测试是否真正失败于旧实现，避免测试复制实现错误或仅测 mock。

### 场景与失败处理

重构把超时异常吞掉并返回空列表，成功路径测试仍通过。审查需追踪调用方是否把空列表当有效“无数据”，并补失败语义测试。

### 常见追问

**让另一个 Agent 审查就足够吗？** 不能保证独立性，关键风险仍需确定性检查和真实证据。

**没有发现怎么写？** 明确未发现问题，并说明已审范围、运行检查和残余风险。
