## 1. 什么时候选择工作流，什么时候选择 Agent？

步骤稳定、规则明确且需要强可控性时，优先使用工作流；路径依赖运行时信息、需要动态选择工具或处理开放问题时，再引入 Agent。回答时要比较确定性、维护成本、失败半径与评估难度。

延伸阅读：[工作流与 Agent](/docs/agent-architecture/agent-architecture/workflow-vs-agent)。

## 2. 单 Agent 和多 Agent 如何选型？

默认先验证单 Agent 是否足够。只有任务可以按能力或上下文边界清晰拆分，并且协作收益高于通信、状态同步和调试成本时，才使用多 Agent。不要把角色名称数量当作架构复杂度的合理性证明。

延伸阅读：[单 Agent 架构](/docs/agent-architecture/agent-architecture/single-agent-architecture)和 [多 Agent 架构](/docs/agent-architecture/agent-architecture/multi-agent-architecture)。

## 3. Agent 工作流如何实现暂停和恢复？

关键是把执行状态持久化为可恢复检查点，并记录下一节点、上下文版本、工具副作用与人工输入要求。恢复时要校验状态是否过期，并避免重复执行已经产生外部影响的步骤。

延伸阅读：[检查点](/docs/agent-development/workflow-state/checkpoint)和 [持久化与恢复](/docs/agent-development/workflow-state/persistence-recovery)。

## 4. 如何设计一个可靠的 Agent 工具？

工具需要单一明确的职责、稳定的输入输出契约和可操作的错误信息。实现时还要处理参数校验、权限边界、超时取消、幂等性、结果大小限制与可观测记录。

延伸阅读：[工具 Schema](/docs/agent-development/tool-development/tool-schema)和 [错误处理](/docs/agent-development/tool-development/error-handling)。

## 5. MCP、A2A 和 AG-UI 分别解决什么问题？

回答重点不是背诵协议，而是区分交互边界：MCP 连接模型应用与上下文、资源及工具；A2A 面向 Agent 之间的任务协作；AG-UI 面向 Agent 与前端之间的事件和状态同步。选型时应结合通信对象、生命周期与互操作要求。

延伸阅读：[MCP](/docs/agent-development/protocols-integration/mcp)、[A2A](/docs/agent-development/protocols-integration/a2a)和 [AG-UI](/docs/agent-development/protocols-integration/ag-ui)。

## 6. Checkpoint 是否保证外部副作用只发生一次？

不能。外部写入成功与保存检查点之间存在崩溃窗口；恢复可能重执行节点。需要业务幂等键、结果查询和适当的事务或补偿设计。框架恢复粒度必须按版本与实际节点边界核对。

延伸阅读：[检查点](/docs/agent-development/workflow-state/checkpoint)。

## 7. 并行、Supervisor 与 Handoff 如何区分？

并行让多个独立任务同时执行；Supervisor 持续负责分配和验收；Handoff 转移处理责任或控制权。可组合，但必须明确状态归属、结果合并和停止条件，不能只给角色起名字。

延伸阅读：[编排主控](/docs/agent-architecture/orchestration-collaboration-patterns/supervisor)。

## 8. 人工批准如何防止被复用于另一笔操作？

审批绑定具体对象、参数摘要、身份、版本和有效期。恢复后重新核对，参数变化或权限撤销则审批失效。审批记录与真实执行分别去重，重复点击不能重复产生副作用。

延伸阅读：[可恢复审批](/docs/agent-development/runtime-environment/human-in-the-loop)。
