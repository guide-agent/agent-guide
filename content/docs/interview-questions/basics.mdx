## 1. Agent 和普通 LLM 应用有什么区别？

回答时应先说明边界：普通 LLM 应用通常完成一次输入到输出的映射；Agent 会围绕目标进行多步决策，并通过工具与外部环境交互。完整答案还应覆盖上下文、工具、编排循环和停止条件。

延伸阅读：[Agent 通识](/docs/agent-general)和 [Agent Loop](/docs/agent-general/agent-basics/agent-loop)。

## 2. 上下文工程和提示词工程有什么区别？

提示词工程主要优化指令本身。上下文工程还要选择、组织和压缩模型在当前决策点看到的信息，包括系统指令、对话历史、检索结果、工具反馈与运行状态。回答时应说明上下文预算和信息优先级。

延伸阅读：[上下文工程](/docs/agent-general/agent-basics/context-engineering)和 [上下文窗口](/docs/agent-general/llm-basics/prompt-context/context-window)。

## 3. Agent 的短期记忆和长期记忆如何划分？

短期记忆服务于当前任务，通常随会话或工作流状态保存；长期记忆跨任务保留用户偏好、历史事实或可复用经验。设计时要回答写入条件、检索方式、更新冲突、过期策略与隐私边界。

延伸阅读：[记忆](/docs/agent-general/agent-basics/memory)。

## 4. Tool Call 的完整生命周期是什么？

模型先根据工具描述选择工具并生成参数，运行时完成参数校验、权限检查和实际调用，再把结构化结果返回模型。工程答案还应覆盖超时、重试、幂等、错误分类、结果截断与审计记录。

延伸阅读：[工具使用](/docs/agent-general/agent-basics/tool-use)和 [工具参数校验](/docs/agent-development/tool-development/parameter-validation)。

## 5. RAG 为什么仍可能产生幻觉？

检索增强生成（Retrieval-Augmented Generation，RAG）只能改善证据供给，不能保证检索结果相关、完整或被模型正确使用。回答时可从召回质量、切分策略、排序、上下文冲突、引用约束和答案验证六个方面展开。

延伸阅读：[RAG](/docs/agent-general/llm-basics/knowledge-retrieval/rag)。
