## 问题：如何评估一个 Agent？

### 回答框架

Agent 评估不能只看最终回答，还要检查完成过程。建议把指标分成四组：

- **任务结果**：成功率、答案正确性、约束满足率。
- **过程质量**：工具选择正确率、参数正确率、无效步骤数、恢复成功率。
- **成本效率**：模型调用次数、令牌量、工具耗时和总费用。
- **运行安全**：越权动作、敏感信息暴露、未经确认的副作用。

测试集应覆盖正常任务、信息缺失、工具失败、冲突指令、长上下文和高风险操作。每个样例需要固定初始状态、允许动作、成功标准与最大预算，保证结果可以复现和比较。

## 问题：Agent 出错时如何定位？

先确定错误发生在哪一层：目标理解、规划、工具选择、参数生成、工具执行、结果解释、状态更新或终止判断。然后回放结构化轨迹，比较“当时可见信息”“实际选择”“预期选择”和“工具真实结果”。

常见定位顺序：

1. 复现同一初始状态和输入。
2. 检查工具原始返回，不只看模型摘要。
3. 核对失败前后的状态差异。
4. 判断问题来自提示、模型、工具契约还是控制逻辑。
5. 添加最小回归样例，再修改实现。
6. 同时验证成功路径与相邻失败路径。

## 问题：为什么只看端到端成功率不够？

相同成功率可能对应完全不同的风险：一个 Agent 可能稳定用三步完成任务，另一个可能频繁走错后碰巧恢复。只看最终结果无法发现成本放大、越权尝试、错误重试和不可复现行为。

因此需要把最终结果指标与轨迹级指标结合，并对关键副作用设置硬性失败条件。
