## 问题：如何设计可靠的 Agent 工具？

### 回答框架

可靠工具应具有窄而明确的职责、可验证的输入模式、稳定的结构化输出和清晰的错误分类。工具描述需要说明前置条件、作用范围、副作用和成功标准，让模型能够判断“何时调用”和“调用后如何验收”。

执行链路至少包含以下保护：

- 使用结构化 schema 校验参数，拒绝未知字段和非法枚举值。
- 对读取、写入、外发和删除操作分级授权。
- 使用幂等键或状态检查避免重复执行副作用。
- 区分可重试错误、业务拒绝和不可恢复错误。
- 保存调用参数摘要、结果摘要、耗时和错误类型。

### 常见误区

- 工具粒度过大，一个调用同时读取、修改并发布结果。
- 只在提示词里要求安全，没有在执行层校验权限。
- 把异常文本直接返回给模型，没有稳定错误码。
- 对所有失败盲目重试，导致重复写入或成本放大。

## 问题：工具调用失败后如何恢复？

先根据错误类型决定策略：限流和临时网络错误可以按预算退避重试；参数错误应重新生成参数；权限或业务规则拒绝不应自动重试；结果不确定时应先读取目标状态，再决定是否补偿。

对于有副作用的操作，恢复流程必须围绕“当前真实状态”展开，不能仅依据模型记忆。必要时使用幂等键、操作日志、补偿动作或人工确认。

## 问题：如何防止提示注入诱导工具越权？

工具权限应由宿主程序控制，而不是由模型生成的文本决定。外部内容一律视为不可信数据，不能把其中的指令提升为系统规则。执行前需要根据用户授权、数据来源、目标对象和动作风险做独立校验；敏感动作应要求显式确认或采用受限凭据。
