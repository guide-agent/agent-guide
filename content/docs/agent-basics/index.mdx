## 问题：什么是 AI Agent？

### 考察点

- 能否区分 Agent、聊天机器人和固定工作流
- 是否理解模型、工具、状态和控制循环之间的关系

### 回答框架

AI Agent 是一个围绕目标持续执行“观察、决策、行动、反馈”循环的系统。语言模型通常负责推理和生成行动建议，但完整 Agent 还需要工具接口、状态管理、终止条件、权限边界和结果验证。

聊天机器人主要生成回复；固定工作流的步骤由开发者预先确定；Agent 则会根据中间反馈动态选择下一步行动。三者不是互斥分类，一个产品可以同时组合使用。

### 常见误区

- 把“调用一次大模型”直接称为 Agent。
- 只描述模型推理，没有说明状态、工具和终止条件。
- 认为自主程度越高越好，忽略成本、可控性和错误扩散。

### 追问方向

- 哪些任务不适合使用 Agent？
- 如何判断应该使用固定工作流还是动态规划？
- Agent 的一次运行需要记录哪些状态？

## 问题：典型 Agent 循环包含哪些阶段？

一个可审计的循环通常包含以下阶段：

1. 读取目标、当前状态与最新观察。
2. 判断任务是否已经完成或必须终止。
3. 生成候选行动并选择下一步。
4. 校验工具名称、参数和权限。
5. 执行动作并记录结构化结果。
6. 验证结果，将新观察合并到状态。
7. 在预算范围内继续循环，或者输出最终结果。

工程实现中应显式设置最大步数、截止时间、费用预算、重复行为检测和人工接管入口。

## 问题：什么时候不应该使用 Agent？

当任务路径稳定、规则明确、容错率低且每一步都能预先编码时，普通程序或确定性工作流通常更合适。例如账务结算、权限判定和数据库迁移不应把关键决策交给开放式模型推理。

判断时可以比较四项指标：任务路径的不确定性、环境反馈的重要性、错误成本、动态决策带来的收益。只有动态决策收益能够覆盖额外成本与风险时，Agent 才有必要。
