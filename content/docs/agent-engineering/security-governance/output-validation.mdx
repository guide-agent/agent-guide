## 面试题：为什么模型输出要按使用场景做不同验证？

### 回答框架

自然语言、SQL、代码、HTML 和工具参数的风险不同。校验要围绕下游如何使用结果：事实回答核对证据，机器消费验证 Schema，执行型输出还要检查权限、业务规则与副作用。一个统一“安全评分”无法替代具体约束。

### 关键机制与取舍

- 区分格式正确、事实正确与可执行授权，任何一层通过都不代表其他层通过。
- 渲染不可信内容时做好转义，执行代码或查询时限制环境、资源和允许动作。
- 对无法确认的结果明确标注，修复次数有限，并防止验证器本身被输出中的指令诱导。

### 场景与失败处理

模型生成只读查询却通过函数调用触发写入。应由数据库账号、语句分析和运行约束共同限制，不能只检查是否以 SELECT 开头。

### 常见追问

**模型自检够吗？** 不够，应优先使用确定性规则、可执行测试和可信来源核对。

**验证失败怎么反馈？** 返回具体失败约束，允许有限修复或人工处理，不静默丢弃用户需求。
