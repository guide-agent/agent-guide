## 面试题：如何让模型错误不会直接变成越权操作？

### 回答框架

把模型视为提出候选动作的组件，权限由可信身份、资源策略和执行器强制实施。提示词能指导行为，但不是授权证明。边界设计要覆盖直接工具调用、子 Agent、后台任务和外部协议接入。

### 关键机制与取舍

- 只暴露当前任务需要的能力，读、写、发布和权限管理按风险分开。
- 资源归属在服务端检查，执行时重新核对授权与审批参数，避免检查与使用之间状态变化。
- 越权拒绝应记录并可解释，但不把密钥、内部策略细节或其他租户信息泄露给模型。

### 场景与失败处理

用户让检索 Agent 修改生产配置，工具列表中不应有该能力；即使模型构造出调用名称，后端也应拒绝执行。

### 常见追问

**多 Agent 共用管理员账号有什么风险？** 无法区分委托范围和责任，单个角色被诱导会扩大影响。

**更严格权限会不会降低可用性？** 需要最小必要权限与清晰升级路径，而非无理由阻断正常任务。
