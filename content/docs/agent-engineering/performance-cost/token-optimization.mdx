## 面试题：怎样减少 token 而不损害任务成功率？

### 回答框架

先测 token 花在哪里：重复指令、冗余工具定义、检索噪声、长结果或反复失败。优化应删除低价值信息并保留约束和证据，不是机械截断。以相同质量和安全门槛下的端到端费用判断收益。

### 关键机制与取舍

- 对大工具结果返回摘要、分页和可按需读取的引用，避免一次注入完整日志。
- 将稳定前缀与动态任务内容合理组织，是否获得缓存收益以供应商实际统计为准。
- 压缩后验证身份、授权、未决事项、关键数值与引用没有丢失。

### 场景与失败处理

把代码报错截成最后一行，漏掉真正的调用位置，导致模型重复修改。应先提取相关堆栈与上下文，必要时按证据位置回读原日志。

### 常见追问

**缩短输出一定省总费用吗？** 若用户需反复追问或产生错误重试，整体费用可能上升。

**是否应该减少思考预算？** 需结合任务难度与可测结果，不能只凭单次响应更短下结论。
