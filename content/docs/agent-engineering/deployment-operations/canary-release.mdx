## 面试题：Agent 灰度发布应观察哪些信号？

### 回答框架

灰度不只是看 HTTP 错误率，还应观察任务成功、错误动作、转人工、耗时与成本。模型、提示、检索和工具变更都值得灰度。先定义门槛和回滚动作，再逐步扩大流量，不用上线后挑选指标证明成功。

### 关键机制与取舍

- 按用户或会话稳定分组，长任务固定版本，避免执行中途切换不兼容策略。
- 影子验证尽量只读或使用隔离环境，不能为了比较效果执行两次真实写操作。
- 回滚前核对旧版本能否读取新状态，并处理已经产生的外部副作用。

### 场景与失败处理

新版 Agent 成功率相近但调用次数翻倍，模型费用明显上涨。成本门槛应触发停止扩量，而不是等账单出现后再排查。

### 常见追问

**如何选择灰度样本？** 覆盖代表性任务和风险切片，不能只给最简单问题。

**回滚能撤销错误退款吗？** 不能自动撤销，外部副作用需要业务补偿或人工处置。
