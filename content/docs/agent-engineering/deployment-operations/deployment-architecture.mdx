## 面试题：Agent 服务部署与普通请求响应服务有何不同？

### 回答框架

Agent 常有长任务、流式响应、外部工具和可恢复状态，不能只按无状态 HTTP 服务设计。控制面负责身份与任务，执行面负责运行与隔离，状态和产物放在可靠存储中。是否拆服务取决于负载与权限需求，不必一开始微服务化。

### 关键机制与取舍

- 长任务用稳定 ID 查询，连接断开不直接决定任务生命周期。
- 按运行环境隔离执行与业务 API，限制工具凭证和网络范围。
- 发布与缩容时先停止接新任务，等待、转移或记录可恢复状态，避免硬杀带副作用的步骤。

### 场景与失败处理

滚动升级杀掉正在提交订单的 worker，用户重新发起导致重复订单。通过幂等键、任务接管和停止接单流程保证可恢复。

### 常见追问

**所有状态都放内存会怎样？** 重启丢失任务与审批，多个副本也难一致，需要按任务持久化。

**必须用 Kubernetes 吗？** 不必须，先满足隔离、恢复和运维要求，部署平台只是实现选择。
