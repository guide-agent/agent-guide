## 面试题：配置和密钥如何管理，才能支持安全回滚？

### 回答框架

配置包括模型、提示、工具地址、限额和策略，密钥提供外部访问能力，两者都要版本和权限管理。密钥不应进入提示、仓库或普通日志；配置变更也可能改变业务行为，应与代码一样可审计和回退。

### 关键机制与取舍

- 区分构建期、启动期与请求期配置，说明变更何时生效，不能把文件已改当运行已生效。
- 按环境与服务限制凭证范围，支持轮换、吊销和失效报警，避免共享长期管理员密钥。
- 启动时校验关键配置组合，缺少必需值时明确失败，不静默切换到不安全默认值。

### 场景与失败处理

只更新环境文件却未重启进程，业务仍使用旧模型。应核对运行时版本标识与一次受控请求，再报告生效；不要在日志输出完整密钥做确认。

### 常见追问

**回滚只改镜像就够吗？** 还要考虑提示、策略、状态 Schema 与外部配置的兼容性。

**密钥能通过模型参数传入吗？** 不应，执行器从可信配置读取，模型只选择已授权能力。
