## 面试题：运行日志与用户会话历史为什么要分开？

### 回答框架

会话历史服务交互与上下文，执行日志服务诊断、审计和恢复证据。两者的保留期限、权限与内容不同：用户能看到的回答不一定包含工具错误，日志也不应无条件暴露给用户。应通过稳定 ID 关联，而不是混成一个文本文件。

### 关键机制与取舍

- 事件记录动作类别、结果、版本和时间，关键业务动作保留可信外部标识。
- 原始敏感内容最小化存储，对访问、下载和删除设置权限与生命周期。
- 区分审计事件与调试信息，避免采样把关键副作用记录丢掉。

### 场景与失败处理

线上只保存最终回答，无法判断“已发邮件”是否真实发生。应保留发送请求和确认状态；但邮件正文和收件人不应无差别进入公共日志。

### 常见追问

**保存越多越好排障吗？** 噪声、成本和泄露风险会增加，应围绕可复核问题设计字段。

**删会话是否也删日志？** 按用途与合规要求分别处理，同时提供可追踪的数据生命周期。
