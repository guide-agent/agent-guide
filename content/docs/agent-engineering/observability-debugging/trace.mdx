## 面试题：Agent Trace 应记录什么才有排障价值？

### 回答框架

Trace 把一次用户任务的模型调用、工具调用、状态变化和产物关联起来，用于解释失败发生在哪一层。它不是把所有原始提示和敏感返回全文存下来，也不要求记录不可见的内部推理。先有轻量结构化事件就能获得主要价值。

### 关键机制与取舍

- 使用任务、步骤和调用关联 ID，记录开始结束、状态、耗时、版本和证据引用。
- 并行分支保留父子关系，错误区分调用失败、业务拒绝和结果未知。
- 敏感字段脱敏并限制访问、保留期限；大附件使用受控引用而非日志复制。

### 场景与失败处理

用户报告“没有退款却显示成功”，Trace 应能串起意图、审批、退款调用和外部交易号，判断是模型误述还是业务提交失败。

### 常见追问

**日志和 Trace 必须用大型平台吗？** 不必，先用统一结构与关联 ID，按规模选择存储和查询方式。

**能靠 Trace 精确复现吗？** 还需要输入、依赖版本和可控外部状态，日志本身不保证确定性。
