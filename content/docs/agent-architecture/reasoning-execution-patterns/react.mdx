## 面试题：ReAct 的价值是不是要求模型写出长篇推理？

### 30 秒回答

ReAct 的核心是边行动边根据反馈调整，不是让模型写很长的思考过程。一次查询发现新线索，再决定下一次查什么。真正有用的记录是采取了什么动作、工具返回什么，以及为何改变方向的简洁说明。

### 用一个例子理解

排查网站慢，先查响应时间，发现数据库阶段耗时高，再查慢查询；如果第一步显示是网络超时，后续调查方向就不同。这个过程靠真实观察推进，不能把模型猜测当成查到的日志。

### 关键机制与取舍

- 工具观察应与调用 ID 关联，不能把模型猜测填作真实结果。
- 每轮验证新增证据是否推动任务，重复失败进入澄清、降级或停止分支。
- 适合路径受实时反馈影响的探索任务；长依赖链可与显式计划结合。

### 场景与失败处理

排查服务超时时先看日志，再按证据查依赖，而不是一次规划所有可能命令。若日志权限不足，应报告缺口，不通过其他身份绕过。

### 常见追问

**ReAct 与普通循环有什么不同？** 下一步动作由当前模型决策与观察共同决定，而非固定顺序。

**怎么防止循环？** 组合步数、时间、成本与无进展检测，并设置有信息量的失败终态。
