## 面试题：概念上的 Agent Loop 上线前还缺哪些控制？

### 回答框架

概念循环只说明“观察、决策、行动”；工程循环还必须管理并发、取消、恢复、错误类别和副作用。把每次动作作为有身份、有状态的执行单元，并让成功标准与预算成为外层约束，而不是任模型自行决定。

### 关键机制与取舍

- 记录 run_id、step_id、动作摘要、结果状态和产物版本，便于回放与审计。
- 超时需要取消或隔离正在运行的任务；返回超时不代表后台写操作已经停止。
- 重试、补偿和恢复分开处理，副作用执行前后存在的不确定窗口必须可查询。

### 场景与失败处理

写入成功后进程在存检查点前崩溃，恢复可能再次写入。使用业务幂等键与外部结果核对，不能认为“有 checkpoint 就不会重复”。

### 常见追问

**所有错误都交给模型处理吗？** 不，认证失败、预算和执行策略由确定性逻辑先处理。

**日志完整就能精确重放吗？** 还需版本、外部状态或录制的工具结果；模型输出也可能不确定。
