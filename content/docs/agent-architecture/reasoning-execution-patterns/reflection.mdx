## 面试题：让模型反思自己的答案，能稳定提高质量吗？

### 30 秒回答

Reflection 是在初稿后增加一次检查和修订。它有用的前提是检查有依据，例如测试失败、原文证据或明确评分标准。让模型反复说“再想想”不保证变正确，也会增加时间和费用。

### 用一个例子理解

模型写的排序函数在空列表上崩溃，测试报告指出这一点，修订就有了明确目标。若只是让同一个模型评价“代码很好吗”，它可能继续认可原来的错误。修好空列表后，还要确认普通输入没有被改坏。

### 关键机制与取舍

- 把生成与评价输入分开，评价器引用可验证证据，不只给模糊分数。
- 保留原始候选与评分变化，避免“修复”引入新的事实错误或删除有效内容。
- 设置迭代上限与接受门槛，成本按完整生成、评价、修订链路统计。

### 场景与失败处理

编码 Agent 自评“没有问题”，但测试暴露空输入崩溃。把失败样例作为反思依据，只修相关边界，再运行原回归集确认没有退化。

### 常见追问

**换一个模型做裁判就独立了吗？** 不一定，训练偏差和输入证据仍可能相同。

**什么时候停止修订？** 满足可验证标准、没有新增改进或预算耗尽时停止，并说明剩余限制。
