从控制流归属出发理解 Agent 架构：先比较固定工作流与自治循环，再学习推理、执行和协作模式。架构的价值在于清晰的责任、状态和失败边界，而不是角色数量。

## 推荐学习路径

先掌握单 Agent 的工具、状态和终止机制，再用同一任务比较 ReAct、显式计划和多 Agent。

## 自测与使用边界

能解释某种模式解决的瓶颈、增加的协调成本，以及失败时由谁恢复。

阅读后尝试不看答案回答主问题，再用失败场景追问自己的设计。概念说明、设计建议与运行结果应分开记录。
