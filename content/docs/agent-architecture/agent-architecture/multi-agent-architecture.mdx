## 面试题：多 Agent 协作为什么既可能增益，也可能放大错误？

### 30 秒回答

多 Agent 是让多个有分工的执行单元合作，不是多开几个聊天窗口就能变强。只有任务能拆开、交接说得清、结果能独立检查时，分工才可能值得。否则通信、重复劳动和意见冲突反而会拖慢系统。

### 用一个例子理解

整理采购建议时，一个角色查价格，一个查兼容条件，最后统一核对来源，适合分工。如果两者同时修改同一份报价表却没有版本规则，就可能互相覆盖；这时先顺序完成比盲目并行更可靠。

### 关键机制与取舍

- 为每个角色定义输入、产物、验收与工具权限，避免所有角色共享全部写权限。
- 使用任务 ID、状态版本和明确的最终负责人；共享数据区与工作区分开，文件修改按所有权管理。
- 将通信 token、重试、等待和最终集成计入成本，对比同预算单 Agent 基线。

### 场景与失败处理

两个编码 Agent 同时修改同一接口，局部测试都通过但集成失败。按接口冻结版本分工，约束文件写入范围，由集成者运行契约测试并处理冲突。

### 常见追问

**多数投票能提高正确率吗？** 只有错误不完全相关且评价信号可靠时才可能有效，需实测。

**任务越碎越好吗？** 碎片化会增加上下文交接与调度开销，应围绕可独立验收的边界拆分。
