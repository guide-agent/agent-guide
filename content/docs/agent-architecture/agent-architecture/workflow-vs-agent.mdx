## 面试题：哪些步骤交给工作流，哪些交给 Agent？

### 回答框架

规则稳定、路径可枚举且副作用重大时，工作流通常更易验证；需要根据未知环境动态检索、判断下一步时，Agent 更有价值。两者不是技术代际关系，而是控制流归属不同。实践中可由工作流规定阶段和权限，让 Agent 在单个阶段内有限探索。

### 关键机制与取舍

- 先列确定性业务规则，再识别真正需要开放决策的环节，避免把所有 if 分支改成模型调用。
- 统一输入输出契约，使自治节点可以失败、替换或退化成规则处理。
- 比较完整任务的成功率、耗时分布与人工介入率，不仅比较模型调用次数。

### 场景与失败处理

报销审批的额度规则不适合让模型自由裁量；票据解释可使用模型，额度校验与打款由确定性程序处理，异常票据转人工。

### 常见追问

**工作流能调用工具吗？** 能，调用工具并非 Agent 的专属能力。

**自治节点失败会拖垮全流程吗？** 取决于边界设计；应能暂停、返回局部结果或切换人工，而不是无限重试。
