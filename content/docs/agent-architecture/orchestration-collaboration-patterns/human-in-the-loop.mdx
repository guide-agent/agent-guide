## 面试题：架构层的人在回路，应在哪些位置介入？

### 回答框架

人在回路是控制流中的明确决策节点，适用于高影响动作、需求歧义、低质量结果和自动恢复失败。它不是给每个步骤弹确认框；人工应看到足够证据并能拒绝、修改或取消。执行层如何保存审批状态见开发栏目的对应专题。

### 关键机制与取舍

- 依据风险与可逆性设置审批点：检索可自动进行，支付、发布或权限变更需按业务策略确认。
- 审批内容绑定动作摘要、参数版本和有效期，避免批准后执行对象悄悄变化。
- 将等待人工计为独立状态，记录超时、交接责任和后续恢复路径。

### 场景与失败处理

Agent 建议批量删除数据，审批人只看到“同意操作”没有对象列表。应展示影响范围和回滚条件，参数改变后旧审批失效。

### 常见追问

**人工批准后就不需要校验吗？** 仍需校验当前状态、权限和参数一致性，审批不是任意执行凭证。

**审批太多怎么办？** 按风险分级、合并同一变更的证据，而非跳过必要的确认。
