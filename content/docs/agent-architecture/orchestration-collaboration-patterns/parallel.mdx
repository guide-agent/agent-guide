## 面试题：什么任务可以并行，什么任务不应该并行？

### 回答框架

并行适合输入已确定、互不依赖、资源或副作用不冲突的子任务。总延迟接近最慢分支再加合并开销，但总费用通常是各分支之和。必须先分析依赖图，不能把有先后关系的动作只因工具支持并行就一起执行。

### 关键机制与取舍

- 设置共享并发上限和预算，每个子任务有截止时间；避免扇出拖垮模型或数据库限额。
- 明确等待全部、达到足够证据或部分成功的合并策略，并区分未返回与失败。
- 输出保留来源和版本，冲突由确定规则或主控仲裁，而不是最后返回者覆盖。

### 场景与失败处理

多源资料检索可并行，但“创建订单”和“支付订单”存在依赖；两个分支同时修改同一文件也可能造成丢失更新。

### 常见追问

**并行一定更快吗？** 不，排队、速率限制和合并开销可能抵消收益。

**某个分支失败怎么办？** 依据其是否为必需输入决定降级、重试或整体失败，不默认忽略。
