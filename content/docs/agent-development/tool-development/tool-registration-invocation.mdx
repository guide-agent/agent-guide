## 面试题：工具从注册到返回结果，如何保持一致性？

### 回答框架

注册层把公开名称和 Schema 映射到允许的实现；调用层解析请求、校验上下文、执行并返回关联结果。模型可见工具集与实际执行权限必须一致，不能出现“未公开但凭名称能调用”的后门。

### 关键机制与取舍

- 使用白名单注册，不把模型给出的字符串当模块路径或任意函数名动态执行。
- 每次调用绑定 run、call、用户与工具版本，流式请求在参数完整后才进入执行阶段。
- 动态发现工具时缓存能力描述，但权限和资源归属在执行当下重新核对。

### 场景与失败处理

租户切换后仍复用上个租户的工具列表，模型请求了不存在的资源。应按身份更新暴露集合，并让后端拒绝越权请求，而不是仅清理前端菜单。

### 常见追问

**同名工具来自多个服务器怎么办？** 使用命名空间和稳定标识，结果中保留实际提供方与版本。

**工具返回丢失时能重调吗？** 先判断副作用与幂等能力，结果未知不等于未执行。
