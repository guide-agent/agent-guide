## 面试题：怎样的 Tool Schema 更容易被模型正确使用？

### 回答框架

Schema 应表达单一清晰动作：什么时候调用、参数含义、约束与结果状态。名称和描述要有区分度，不把复杂业务规则藏在泛化的 execute 工具里。Schema 是沟通契约，服务端仍须对相同约束进行真实检查。

### 关键机制与取舍

- 对单位、时区、资源标识、枚举与可空性明确约定；金额不能只写一个没有币种的 number。
- 把只读预览与有副作用执行分开，少用同时控制十几种动作的可选参数组合。
- 返回结构区分成功、业务拒绝、待确认与系统错误，错误信息指导修正但不暴露敏感细节。

### 场景与失败处理

工具参数叫 date，模型传入本地日期而服务按 UTC 解释。改为明确的时间范围与时区，并在调用前检查起止关系，加入跨日测试。

### 常见追问

**描述越长越好吗？** 不一定，重复和矛盾会降低选择质量，应保留必要条件及关键反例。

**工具改名会影响什么？** 影响提示、模型选择、注册映射和历史轨迹解释，应版本化并回归。
