## 面试题：参数已经符合 Schema，为什么仍要业务校验？

### 回答框架

Schema 可以验证类型与局部约束，但资源是否属于用户、状态是否允许操作、额度是否充足需要真实业务数据。参数验证应分成结构、语义、权限和当前状态几个层次，且关键检查靠近最终执行位置。

### 关键机制与取舍

- 规范化路径、时间与标识后再验证，避免编码差异、符号链接或单位转换绕过限制。
- 从可信身份上下文获取租户和权限，不相信模型传来的角色字段。
- 对并发状态变化使用版本条件或事务，避免检查通过后数据已改变。

### 场景与失败处理

Agent 在预览时看到余额充足，执行前余额被其他订单占用。最终扣款仍需事务检查；把预览结果作为永久授权会出现超额。

### 常见追问

**参数不对应该自动修吗？** 无歧义格式可规范化，涉及金额、对象或意图的改变应澄清或重新确认。

**前端做了校验还要后端吗？** 要，前端不是执行安全边界，模型和其他客户端可绕开它。
