## 面试题：工具错误怎样返回，才能支持正确恢复？

### 30 秒回答

工具报错先分类型，再决定动作：临时故障可有限重试，缺参数需要补问，权限不足应停止，写操作结果未知则先查状态。统一告诉模型“失败了，再试一次”，既浪费预算也可能重复操作。

### 用一个例子理解

查天气超时可以短暂等待后重试；订单退款超时却不能这样处理，因为钱可能已退。要先用这次退款的业务编号查询结果，确认未执行后才重试。这里“超时”描述的是没有及时收到响应，不等于服务没做事。

### 关键机制与取舍

- 统一错误码、可读摘要、可重试标记和必要的关联 ID；内部堆栈与敏感响应留在受控日志。
- 权限错误不尝试换身份绕过，输入缺失可向用户澄清，临时故障在预算内退避。
- 对有副作用操作，返回“已提交但确认失败”与“未开始”两种不同状态。

### 场景与失败处理

发邮件 API 超时，直接返回失败后重发可能产生两封邮件。应保留发送请求 ID 并查询投递状态，无法确认时向用户说明不确定性。

### 常见追问

**retryable=true 就能无限重试吗？** 不能，还受次数、截止时间、费用和副作用约束。

**把异常全文交给模型更好吗？** 通常不是，过多噪声和秘密字段会增加风险，保留诊断所需信息即可。
