## 面试题：工作流编排要管理哪些信息，而不只是画一张 DAG？

### 回答框架

DAG 描述依赖，但真实任务还需要状态转移、条件分支、失败传播、人工等待和取消。含循环的 Agent 流程不一定是 DAG，应明确允许回边和终止条件。编排器负责推进任务，业务节点负责限定职责。

### 关键机制与取舍

- 节点产物使用稳定契约，前置依赖以实际完成状态判断，不仅依赖执行顺序。
- 并行合并明确必需分支、部分结果与错误传播方式，防止静默丢失失败。
- 副作用节点与审批、查询节点分开，重试策略按节点风险设置。

### 场景与失败处理

报告流程并行取两个数据库，一个超时却仍生成“全量报告”。合并节点应标明覆盖范围，必需数据缺失时停止或明确降级。

### 常见追问

**工作流必须持久化吗？** 短暂无副作用任务可轻量处理，跨进程、人工等待或昂贵任务通常需要。

**状态图能保证业务正确吗？** 不能，节点契约、数据质量与验收仍需要测试。
