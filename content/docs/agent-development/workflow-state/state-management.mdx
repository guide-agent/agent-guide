## 面试题：为什么不能把所有运行状态都藏在聊天历史里？

### 回答框架

聊天记录适合表达交互，不适合作为精确状态机。金额、版本、已完成动作、审批与下一节点应保存为结构化状态，模型上下文只是其投影。这样才能处理并发、恢复、检索和审计，也能避免摘要丢失关键字段。

### 关键机制与取舍

- 区分不可变事件、当前状态快照和临时上下文；每次更新带任务与版本标识。
- 并发写入使用唯一所有者、乐观锁或明确合并规则，不能靠“最后一句话”决定真相。
- 大产物存引用与校验信息，避免把所有日志和文件内容塞入状态数据库。

### 场景与失败处理

两个分支都更新任务完成列表，后写覆盖前写。使用版本冲突检测或集合合并，并区分不同分支的所有权，合并后验证完整性。

### 常见追问

**状态和记忆有什么区别？** 状态服务当前执行正确性；长期记忆服务跨任务复用，生命周期与精度要求不同。

**模型可以直接修改任意状态字段吗？** 不应，关键字段经工具与状态转换规则校验。
