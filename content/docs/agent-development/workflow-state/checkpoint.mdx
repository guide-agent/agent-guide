## 面试题：Checkpoint 应保存什么，不能保证什么？

### 30 秒回答

Checkpoint 是任务的存档：记住做到哪一步、已经得到什么结果、下一步是什么。它让程序中断后有机会接着做，但不会把外部世界一起倒回存档时刻。已经发出的邮件、扣过的钱，不会因为恢复存档而撤销。

### 用一个例子理解

任务先发送提醒邮件，再保存“已发送”。如果邮件已发出但保存前断电，旧存档仍显示“未发送”，重跑就会重复发信。应给这次业务动作一个固定编号，恢复时先查发送结果，再决定要不要重试。

### 关键机制与取舍

- 记录任务 ID、步骤、输入版本、已确认动作及等待条件，避免只有一段聊天摘要。
- 检查点写入成功与外部动作成功存在顺序窗口，需要幂等键、事务消息或对账弥补。
- 版本升级前测试旧检查点兼容性，不能把无法反序列化的任务静默重置。

### 场景与失败处理

LangGraph 节点在 interrupt 前执行外部写入，恢复从节点开头重跑可能再写一次。可拆分审批与副作用节点，并为副作用本身设计幂等。

### 常见追问

**保存更频繁就一定更可靠？** 会提高存储开销，仍无法消除跨系统原子性问题；选择有意义边界。

**检查点能作为备份吗？** 不完全，外部产物和依赖数据也需要独立保留。
