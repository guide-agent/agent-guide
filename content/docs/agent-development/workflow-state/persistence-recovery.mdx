## 面试题：进程崩溃后，如何安全恢复一个未完成任务？

### 30 秒回答

持久化是把任务状态写到进程退出后仍在的存储里；恢复是读取这些状态后，确认哪些步骤能安全继续。两者不能只保存聊天文本，还要保存任务身份、结果位置、版本和外部动作的确认状态。

### 用一个例子理解

生成报表时，进程算完数据却在上传后断线。恢复时先检查目标文件是否已存在且内容正确，再决定重传；如果把整个任务从头执行，可能重复发送报表通知。

### 关键机制与取舍

- 通过租约或状态条件更新获得执行权，租约过期也要防止旧执行者继续提交结果。
- 对结果未知的写操作查询目标系统，不把本地没有成功记录等同于外部未执行。
- 恢复后重新检查授权有效期、输入版本和剩余预算，过期任务进入人工处理。

### 场景与失败处理

后台创建工单成功，进程在保存工单号前退出。用稳定业务请求 ID 查找既有工单，补齐本地状态，而不是重建一张。

### 常见追问

**Exactly-once 能由队列保证吗？** 消息投递语义不等于外部业务副作用恰好一次，仍需端到端幂等设计。

**什么时候放弃自动恢复？** 无法确认动作结果、授权过期或状态无法兼容时，应保留证据并交接。
