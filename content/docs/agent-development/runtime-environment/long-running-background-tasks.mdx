## 面试题：长任务如何支持查询、取消与恢复？

### 回答框架

把长任务从请求连接中解耦，使用稳定任务 ID、持久状态和可查询产物。HTTP 超时或用户关页不代表任务自动取消。队列负责调度，worker 负责执行，控制面负责授权与状态查询，各自生命周期需要清楚。

### 关键机制与取舍

- 状态区分排队、运行、等待人工、完成、失败和取消中；取消成功需有执行侧确认。
- 心跳、租约与断点用于发现失联执行者，重新分派前检查旧任务是否仍可能提交。
- 按用户和任务限制并发与预算，定期落盘进度和产物引用，不把所有中间内容发回前端。

### 场景与失败处理

后台生成报告耗时十分钟，用户反复点击造成多个作业。提交时按业务幂等键复用任务，允许查询已有进度，并在取消时处理进行中的下载或写入。

### 常见追问

**重启 worker 就算恢复了吗？** 不是，还要恢复状态、核对外部结果并避免多个执行者竞争。

**进度百分比怎么算？** 依据实际阶段或工作量，未知剩余量时报告阶段和已完成项，不伪造线性进度。
