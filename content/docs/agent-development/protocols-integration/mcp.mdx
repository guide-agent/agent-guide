## 面试题：MCP 统一了什么，又没有替系统解决什么？

### 回答框架

MCP 规范模型应用与上下文服务的交互。Host 管理应用和连接，Client 与 Server 通信，Server 暴露工具、资源等能力。它降低接入协议差异，但不自动证明工具可信，也不替代租户授权、业务校验与结果验证。

### 关键机制与取舍

- 先协商协议与能力，再发现和使用服务；不同传输方式的部署和认证边界需单独确认。
- 工具描述、资源内容和执行结果仍是不可信输入，不能提升为宿主最高权限指令。
- 凭证限定到目标服务和用户，注意跨服务代理造成的混淆代理风险，不随意转发令牌。

### 场景与失败处理

一个检索 Server 在结果中要求上传本地密钥。MCP 消息合法不代表指令合法，Host 应把它作为资料内容处理并拒绝越权动作。

### 常见追问

**MCP 就是 Function Calling 吗？** 不是；前者规范应用与服务的交互，后者通常是模型表达动作请求的机制，可配合使用。

**工具列表能长期缓存吗？** 可按协议与业务策略缓存，但能力变化和权限变化需要刷新或重新验证。
