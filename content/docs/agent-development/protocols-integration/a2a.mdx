## 面试题：A2A 与普通调用另一个 Agent 的 HTTP 接口有什么差别？

### 回答框架

A2A 提供 Agent 间发现能力、交换消息、管理任务状态和产物的共同模型，便于跨实现协作。它不要求暴露内部推理或工具实现，也不保证对方输出可信。是否采用要看互操作和长任务生命周期需求，而非仅因为有多个角色。

### 关键机制与取舍

- 理解 Agent Card、Message、Task 和 Artifact 的职责，区分即时响应与持续运行任务。
- 保留任务与上下文标识，处理等待输入、取消、失败和产物更新，不把连接关闭等同于任务结束。
- 能力描述不是授权；对等方身份、数据最小化和委托范围需独立落实。

### 场景与失败处理

远端分析任务需要半小时，本地请求超时后重新提交可能重复计算。保存远端任务标识并查询或订阅进度，明确取消请求是否真正生效。

### 常见追问

**A2A 会替代 MCP 吗？** 通常不，二者分别侧重 Agent 协作与工具/上下文接入，可以同时存在。

**对方说任务完成就接受吗？** 还需校验产物格式、来源、业务约束和必要证据。
