## 面试题：AG-UI 如何帮助前端呈现 Agent 的运行过程？

### 回答框架

AG-UI 面向 Agent 与用户界面的事件和状态交互，让前端不只接收最终文本，还能呈现消息、工具活动、运行阶段与状态变化。协议统一表达，不替代应用的会话鉴权、事件存储与交互设计。

### 关键机制与取舍

- 区分运行生命周期、消息增量与业务状态更新，避免用一条不断拼接的字符串承载所有语义。
- 断线后按选用实现的能力恢复状态；快照、增量、顺序与去重规则必须明确，不能假定协议自动提供持久重放。
- 面向用户只展示适当的动作摘要与证据，不默认公开内部提示、秘密或不可见推理。

### 场景与失败处理

用户刷新页面后重复应用工具完成事件，界面误显示两笔订单。渲染层按稳定事件或业务标识去重，真实业务状态由后端确认。

### 常见追问

**SSE 本身就是 AG-UI 吗？** 不是，SSE 是传输方式，协议还定义事件和状态语义。

**前端“批准”事件能直接执行工具吗？** 不能，后端需要验证身份、动作版本和审批有效性。
