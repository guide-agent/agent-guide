## 面试题：如何做框架选型，避免只列功能对勾？

### 回答框架

先写业务验收场景，再让候选框架完成相同场景。功能名称相同不代表语义相同：都称为 checkpoint，保存粒度和恢复行为可能不同。选型结果应是对当前约束的判断，而不是永久排名。

### 关键机制与取舍

- 比较控制流表达、持久状态、人工恢复、工具协议、流式事件和部署依赖，并标明必须项。
- 用“写操作后崩溃”“审批期间重启”“工具流式中断”等用例验证边界，不只跑顺利路径。
- 同时估算学习、运维、锁定和升级成本；版本与语言实现需分别核对。

### 场景与失败处理

候选 A 演示少写很多代码，但恢复会重执行业务步骤；候选 B 需更多适配却能清晰管理外部事务。若业务涉及付款，恢复语义比演示行数更重要。

### 常见追问

**LangGraph 与 Agent SDK 谁更好？** 前者强调显式状态图的场景很常见，后者依产品提供运行抽象；用实际生命周期需求比较，不预设赢家。

**如何留下可复核依据？** 记录版本、用例、失败证据和取舍，不填未执行的性能数字。
