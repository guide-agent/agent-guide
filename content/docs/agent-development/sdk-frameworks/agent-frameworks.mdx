## 面试题：为什么使用 Agent 框架，又什么时候不需要？

### 回答框架

框架把常见状态、图编排、工具接入和流式事件抽象成可组合组件，降低重复实现成本。代价是学习成本、默认行为与升级耦合。任务只有少量固定步骤时，清晰的普通程序可能更易维护，不能为了“Agent 化”强行引入框架。

### 关键机制与取舍

- 围绕状态、重试、中断和可观测需求做最小验证，不以示例运行成功代替生产能力确认。
- 保留领域逻辑和数据模型的独立性，避免所有业务状态依赖框架私有对象。
- 以故障注入验证恢复语义，例如节点重执行是否重复发送通知。

### 场景与失败处理

图框架支持检查点，但节点内先写外部系统再暂停。恢复重跑节点导致重复通知；应调整副作用边界并加入幂等控制，而不是只开启存储插件。

### 常见追问

**自研是否一定更可控？** 不是，自研也要承担兼容、恢复和观测成本，需比较总维护负担。

**框架升级怎么验证？** 固定典型运行轨迹和契约，重点回归工具、状态序列化与中断恢复。
