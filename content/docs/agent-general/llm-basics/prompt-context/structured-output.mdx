## 面试题：输出合法 JSON，是否代表结果可以直接执行？

### 30 秒回答

结构化输出让回答按指定字段和类型组织，例如固定的 JSON 对象。它解决“程序能否读懂格式”，不能证明字段内容真实、有权限或符合业务规则。执行工具前，仍要做独立校验。

### 用一个例子理解

退款请求的金额是数字、订单号是字符串，格式就可能合格。但订单是否属于当前用户、金额是否超过实付、是否已经退过，都必须查业务系统。格式正确，就像表格填齐了，不等于审批通过了。

### 关键机制与取舍

- 明确必填字段、枚举、范围与未知值表达；不要让缺失信息被默认值悄悄补成真实事实。
- 为拒绝、截断、工具错误和正常结果设计不同状态，流式参数收齐且验证后再执行。
- 有限修复只针对格式或可解释的参数错误；重复失败应返回可行动错误，而不是无限请求模型重写。

### 场景与失败处理

模型给出格式正确的退款对象，但订单属于另一用户。JSON 校验会通过，服务端仍须按会话身份核验订单归属，不能信任模型生成的 user_id。

### 常见追问

**约束解码解决什么？** 主要限制可生成结构，业务事实与跨字段一致性仍需独立校验。

**Schema 改版怎么做？** 显式版本化并做兼容测试，避免旧消费者把新枚举当成功状态。
