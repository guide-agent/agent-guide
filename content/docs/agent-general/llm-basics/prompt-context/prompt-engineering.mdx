## 面试题：如何迭代提示词，而不是凭感觉改几句话？

### 30 秒回答

提示词工程是把任务、输入、限制和完成标准说清楚，让模型少猜。先写清楚要做什么，再给必要资料、输出要求和少量示例，最后用真实样例比较效果。提示词是指导，不是权限控制或事实保证。

### 用一个例子理解

“帮我分析投诉”太宽泛。可以改成“根据这条工单，输出问题类别、原文证据和是否需要人工处理；没有订单号就标为缺失，不要补造”。好坏要看未见过的工单能否处理，而不是示例答案是否漂亮。

### 关键机制与取舍

- 少样本示例覆盖边界与反例，并保证格式一致；示例本身也消耗上下文和可能带来偏差。
- 将指令与不可信文档分开组织，标记来源；权限控制仍由程序执行，不能只写“不要越权”。
- 一次改变一个主要因素，固定模型与工具版本，记录成功率、误拒率、成本和失败切片。

### 场景与失败处理

客服提示“始终帮助用户”导致凭空承诺退款。应给出退款规则、证据要求和无法判断时的转人工路径，同时由退款工具检查真实权限与订单状态。

### 常见追问

**需要模型展示完整思考过程吗？** 不需要；要求简洁决策依据、证据引用和可验证结果即可，轨迹记录实际工具行为。

**提示词能代替微调吗？** 不是同一层次；先用低成本基线验证，稳定行为学习与频繁更新知识应分别评估微调和检索。
