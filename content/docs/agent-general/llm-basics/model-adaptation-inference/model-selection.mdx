## 面试题：如何为 Agent 选择模型，而不是只看排行榜？

### 30 秒回答

选模型不是只看榜单分数，而是看它能否在你的题目上，以可接受的时间和费用完成任务。先固定一组业务样例和通过标准，再比较质量、延迟、费用、工具能力和数据处理要求。小模型够用就不必每次都调用大模型。

### 用一个例子理解

“把工单分成三类”和“核对长合同里的矛盾条款”难度不同。前者可以先测小模型，后者可能需要更强的长文理解能力。即使榜单更高，新模型也可能不遵守你原来的输出格式，因此切换前要跑原业务测试。

### 关键机制与取舍

- 设置不可妥协的门槛：权限安全、结构化输出、上下文需求和数据处理条件，先过滤再比较质量。
- 用相同工具、提示版本和测试集，统计成功任务成本及失败严重度，保留重复运行的不确定性。
- 评估限流、服务稳定性、回退模型能力和版本迁移；回退不能把敏感数据送到未批准区域。

### 场景与失败处理

小模型能回答 FAQ，却频繁把金额单位传错。可保留 FAQ 路由，涉及金额的流程改用确定性解析或更强模型，并在工具入口强制检查单位，而非全站一刀切升级。

### 常见追问

**大模型一定比小模型慢吗？** 不一定，部署方式、负载、输出长度和基础设施也会影响延迟。

**何时重新选型？** 任务分布、模型版本、价格或权限要求变化时，重跑固定回归集和线上小流量验证。
