## 面试题：系统设计面试如何推进，而不是一开始画大架构？

### 回答框架

先澄清需求与规模，列出假设和成功标准，再给最小闭环与主要数据流。随后根据面试官关注点展开存储、工具、安全、恢复和容量。每个组件都要能说明解决哪个约束，以及去掉后会发生什么。

### 关键机制与取舍

- 区分功能与非功能要求，主动确认是否允许真实写操作和人工等待。
- 估算任务量、每任务调用次数和占用时间，数字标明是假设而非实测。
- 优先讲最危险失败路径，再讨论扩展与优化，避免空泛罗列技术。

### 场景与失败处理

设计企业知识助手时，先明确文档权限和更新频率，再讨论切片、检索与生成；若忽略权限，即使检索效果优秀也无法上线。

### 常见追问

**被问到不熟悉的框架怎么办？** 说明可确认的机制与待核实的 API，先讲设计边界，不编造接口。

**复杂度有限时如何取舍？** 保留闭环、数据和权限边界，把高并发与多 Agent 标为后续扩展条件。
