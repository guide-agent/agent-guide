## 面试题：如何设计一个不会随意修改生产数据的 Data Agent？

### 回答框架

先区分数据解释、查询生成和实际执行。模型使用受控 Schema 与业务口径生成查询候选，经权限、语句、资源预算和结果校验后才执行。默认只读并不意味着无风险，查询也可能暴露数据或压垮数据库。本页是系统设计说明。

### 关键机制与取舍

- 把用户身份映射到行列级访问范围，金额、时区、指标口径来自可信数据字典。
- 限制查询时长、扫描范围和返回行数，必要时先解释执行计划，在只读副本或隔离环境验证。
- 结果同时给出时间范围、过滤条件、样本缺失和查询依据，避免把相关性说成因果。

### 场景与失败处理

“最近一个月收入”可能指自然月、近三十天或已结算收入。先澄清口径，再验证聚合与去重；SQL 可运行不等于业务答案正确。

### 常见追问

**只允许 SELECT 就安全吗？** 不充分，函数、副作用、权限和资源消耗都需独立限制。

**如何评测？** 用带口径和预期结果的查询集，覆盖越权、空表、重复行、时区与 NULL。
