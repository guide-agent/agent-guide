## 面试题：面试中如何讲清 Agent 系统架构？

### 回答框架

沿一条请求的数据流讲：入口身份、任务状态、上下文与检索、决策循环、工具执行、结果验证和反馈。再解释状态在哪里、权限在哪里执行、失败如何恢复。组件名称可以不同，但这些边界必须闭合。

### 关键机制与取舍

- 区分控制面、执行面与存储，说明哪些同步、哪些异步以及如何关联任务。
- 关键接口给出输入输出与错误语义，避免用一张包含很多技术 Logo 的图代替设计。
- 从单一任务到多租户、高并发逐步展开，并标出仍依赖假设的部分。

### 场景与失败处理

数据库写入由模型直接生成并执行会把语言判断变成权限边界。应通过窄业务工具和服务端校验，将决策与执行分开。

### 常见追问

**先拆成微服务好吗？** 不必，先按职责分模块，只有隔离、伸缩或组织边界需要时再独立部署。

**架构里最先验证什么？** 业务闭环、权限与失败恢复，其次再优化吞吐和复杂协作。
