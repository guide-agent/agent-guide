## 面试题：接到“做一个 Agent”需求，首先要澄清什么？

### 回答框架

先确定用户、业务目标、当前基线、允许动作和可接受错误，再讨论模型与框架。把任务拆成输入、期望产物、外部依赖和验收标准，识别真正需要动态决策的部分。Agent 是实现选择，不是需求本身。

### 关键机制与取舍

- 列出正常、歧义、无权限和外部失败场景，明确什么情况必须拒绝或转人工。
- 确认延迟、费用、数据范围与人工投入约束，避免只写“准确率高”。
- 区分必须完成与可选增强，先用最小任务闭环验证价值，再扩大自治范围。

### 场景与失败处理

需求是“自动回复客户”，但退款和承诺赔偿未经授权。应先限定知识问答与工单草稿，真实退款单独设计授权流程。

### 常见追问

**业务方说不清指标怎么办？** 用真实任务样本共同定义合格与不合格输出，并记录暂定标准。

**如何判断是否值得做？** 比较现有人工或规则流程的成本与效果，不能只展示一个流畅 Demo。
