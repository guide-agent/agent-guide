## 面试题：技术选型怎样体现权衡，而不是堆技术栈？

### 回答框架

把需求变成必须满足的约束和可比较的目标，先排除不符合权限、生命周期或运行环境的方案，再用小规模验证比较。选型需要说明没有选择另一方案的理由，以及什么条件下会重新评估。

### 关键机制与取舍

- 模型、检索、编排与存储分别选型，不把整套生态当作不可拆的套餐。
- 对恢复、工具契约、版本兼容和运维复杂度进行实际验证，不只看功能清单。
- 成本包含人力、依赖运维、迁移和锁定，公开基准只作为候选线索。

### 场景与失败处理

小型知识库未必需要分布式向量数据库；先确认数据量、过滤和更新需求，以可复现实验比较轻量方案，避免提前引入不必要运维。

### 常见追问

**选型后能改吗？** 应通过接口与版本边界降低替换成本，但不要为所有可能未来搭建过度抽象。

**没时间做全量比较怎么办？** 记录限制、最关键验证与可回退路径，不声称已经证明最优。
