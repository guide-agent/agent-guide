## 面试题：技术故障复盘怎样避免只归因“模型幻觉”？

### 回答框架

从影响、时间线和证据开始，找到最早失效的系统边界，再区分触发条件与根因。模型可能提出错误动作，但业务系统是否缺少校验、回滚或观测同样关键。以下场景是教学示例，不是本站生产事故记录。

### 关键机制与取舍

- 记录用户影响、数据范围、发现方式和止损过程，未知部分明确列出。
- 检查为何测试、权限或监控没有提前拦截，避免把责任归给单个人或一个提示词。
- 每个改进项对应负责人、验收证据与期限，并补充可重现的回归用例。

### 场景与失败处理

示例：创建订单超时后重试导致重复订单。止损暂停自动重试，核对业务请求 ID，再补幂等约束、结果查询和超时恢复测试。

### 常见追问

**重试导致事故，取消重试是否足够？** 不够，仍要处理用户重复提交和进程恢复，根本是业务幂等边界。

**没有完整日志能下结论吗？** 只能报告证据支持的范围，区分已确认事实与待验证假设。
