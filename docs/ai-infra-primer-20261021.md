## 资料筛选和采用边界

检索方式为从用户给定目录按 GPU 基础、显存、K8s 设备模型、硬软切分、NVIDIA 软件栈、DRA、控制面、GPU 指标八个主题定向读取，不以浏览全书代替需求判断。已读章节均带“草稿”标记。

- 采用：基础资源区别、软件栈职责、分配与使用分层、控制与隔离边界，以及先区分 OOM 类型再定位的排障思路。
- 未采用：相互不一致的 DRA GA 版本、未验证的 CEL 属性表达式、普遍化的共享热调整承诺、固定监控字段编号与阈值、单进程显存固定开销等。
- 校准：不把框架 reserved 等同于 nvidia-smi 全部占用；不凭 reserved 与 allocated 差值直接诊断碎片；不把退出码 137 当 GPU OOM 证明；不把所有软件共享都当显存配额机制。
- NVIDIA 官方说明确认相关 GPU 利用率是采样窗口内 kernel 执行时间比例，CUDA 相关版本字段不等于应用 Toolkit 安装版本。具体字段随工具版本变化，不把页面新名称写成所有环境已存在。
- PyTorch stable 文档入口返回 HTML 跳转，沿其明确链接读取 `https://docs.pytorch.org/docs/2.14/notes/cuda.html` 的显存管理正文。只采用缓存、allocated 与 reserved 的职责说明，不发布分配器配置建议或要求升级 PyTorch。
- Context7 的 Kubernetes 官方索引包含较新的 API 特性状态；只用基础对象与扩展设备资源说明，没有据此更新本项目的部署版本承诺。
